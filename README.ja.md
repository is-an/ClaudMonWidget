# ClaudMonWidget

[English](README.md) · [한국어](README.ko.md) · **日本語** · [简体中文](README.zh-CN.md) · [Español](README.es.md)

Claude Code の使用量を表示する、半透明で常に最前面の Windows ウィジェット。

```
┌──────────────────────────────────┐
│  ● 54%                   2h 57m  │
│  ▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░  │
│  6%                       6d 4h  │
│  ▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │
└──────────────────────────────────┘
```

インストールするランタイムはありません。Windows に最初から入っている
PowerShell 5.1 と WPF だけで動きます。`npm install` も別途のログインも不要です
— Claude Code が保存済みの認証情報をそのまま使います。

## インストール

Windows 10/11 に Claude Code が入っていてログイン済みなら、前提はそれだけです。

```powershell
git clone https://github.com/is-an/ClaudMonWidget.git
cd ClaudMonWidget
```

ZIP をどこかに展開しても構いません。場所は問いませんが、ウィジェットが
`config.json` と `usage-cache.json` を自分のフォルダーに書き込むため、書き込み
権限が必要です。`C:\Program Files` の下は避けてください。

インストーラーもレジストリ登録もありません。削除はフォルダーごと消すだけです
（[自動起動](#自動起動)を設定していれば、先にその解除を）。

## 起動

**`ClaudMonWidget.exe`** をダブルクリックします。コンソール ウィンドウは出ません。

自分でコンパイルしていないバイナリを実行したくない場合は、`start-hidden.vbs` が
同じことをします。コンソールから直接起動する場合:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File widget.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File widget.ps1 -Skin detail
```

`-ExecutionPolicy Bypass` はその起動にだけ効きます。システムのポリシーは変えま
せん。

exe は 46KB のランチャーであって、ウィジェットを再パッケージしたものではありま
せん。自分のフォルダーの `widget.ps1` をコンソールなしで起動する、それだけです。
ウィジェット本体は読んで編集できる素の PowerShell のままです。自分で作り直すには
[ビルド](#ビルド)を参照してください。

ウィジェットは**同時に 1 つだけ**動きます。すでに起動しているときに再度実行する
と、2 つ目は何も言わずに終了します。ウィジェットが画面に積み重なり、その一番上が
古い値を表示する事故を防ぐためです。

## 自動起動

### Windows 起動時

1. `Win+R` → `shell:startup` でスタートアップ フォルダーが開きます。
2. `ClaudMonWidget.exe` の**ショートカット**をそこに置きます。

解除はそのショートカットを削除するだけです。

### Claude Code 起動時

Claude Code のセッション開始時にウィジェットを立ち上げます。Claude を使っている
間だけ欲しい場合はこちらが向いています。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install-hook.ps1
```

`~/.claude/settings.json` の `hooks.SessionStart` に項目を 1 つ追加します。既存の
フックと設定はそのままで、実行前に同じフォルダーへタイムスタンプ付きのバックアップ
を残します。複数回実行しても項目は重複しません。

解除:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install-hook.ps1 -Uninstall
```

手で書く場合はこの形です:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "wscript.exe \"C:\\パス\\ClaudMonWidget\\start-hidden.vbs\""
          }
        ]
      }
    ]
  }
}
```

フックはセッションごとに実行されますが、ウィジェットは単一インスタンスなので
2 回目以降は即座に終了します。

**Claude Code を終了してもウィジェットは残ります。** ウィジェットの右クリック
メニューの `Exit` で閉じてください。セッション終了時に一緒に閉じるには停止フック
でプロセスを落とす必要がありますが、それは他の Claude セッションが開いている間も
発動してしまうため、含めていません。

## 操作

| 操作 | 結果 |
|---|---|
| ドラッグ | 移動。位置は終了時に `config.json` へ保存 |
| ホバー | ツールチップ: ウィンドウ開始時刻、課金トークン、キャッシュ読み取りトークン、データ元 |
| 右クリック | メニュー |

メニュー:

- **Skin** — `simple1` / `simple2` / `border1` / `border2` / `detail`。1 つだけ選択。
- **Opacity** — 55 / 75 / 92 / 100%。1 つだけ選択。
- **Always on top** — 最前面の切り替え。
- **Auto sync** — 5 分ごとに Anthropic へ問い合わせる切り替え。
- **Sync now** — 今すぐ Anthropic へ問い合わせる。
- **Refresh now** — ローカル ファイルだけ読み直す。
- **Exit** — 終了。

## スキン

5 つ。末尾の `1` は 5 時間セッションのみ、`2` は 7 日間の枠も表示します。

| 名前 | 幅 | 内容 |
|---|---|---|
| `simple1` | 150 | 背景なし、5 時間の数値だけ |
| `simple2` | 250 | 背景なし、5 時間と 7 日間の 2 列 |
| `border1` | 270 | 角丸のピル + 5 時間バー |
| `border2` | 270 | 角丸のピル + 5 時間・7 日間バー |
| `detail` | 300 | ユーザー名とプラン バッジ、両方のバー、トークン数とリクエスト数、データ元 |

既定は `border2`。高さは内容に合わせて決まるので、フォント倍率を上げた環境でも
文字が切れません。

どちらの枠も次のリセットまでの**残り時間**を表示します。単位は規模に合わせて
変わります — 5 時間の枠は `3h 04m`、7 日間の枠は `6d 5h`。`149h 05m` は頭に
入りません。

```
simple1              simple2
  ● 54%              ● 54%  │  6%
   2h 57m              2h 57m │  6d 4h

border1                          border2
┌──────────────────────┐  ┌──────────────────────┐
│ ● 54%        2h 57m  │  │ ● 54%        2h 57m  │
│ ▓▓▓▓▓▓▓░░░░░░░░░░░░  │  │ ▓▓▓▓▓▓▓░░░░░░░░░░░░  │
└──────────────────────┘  │ 6%              6d 4h│
                          │ ▓░░░░░░░░░░░░░░░░░░  │
                          └──────────────────────┘
```

`detail`:

```
ANIN                        [Pro]
─────────────────────────────────
● 5時間セッション          2h 57m
54%
▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░
6%                         6d 4h
▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
```

どちらの行も同じ規則です。左に使用率、右に残り時間。

色の段階: 70% 未満は緑、70% 以上は黄、90% 以上は赤、値がなければ灰色。

## 数値の取得方法

取得元は 3 つ。新しい順に使います。

### 1. Anthropic に直接問い合わせる（既定で 5 分ごと）

```
GET https://api.anthropic.com/api/oauth/usage
Authorization: Bearer <アクセス トークン>
anthropic-beta: oauth-2025-04-20
```

Claude Code が `/usage` を描くときに呼ぶのと同じエンドポイントです。したがって
ウィジェットの % は `/usage` が見せる値と同じです。

トークンは Claude Code が保存済みのものを読みます:

```
%USERPROFILE%\.claude\.credentials.json  →  claudeAiOauth.accessToken
```

ウィジェットはログインを求めませんし、トークンを上のリクエスト ヘッダー以外の
どこにも送りません。期限切れなら呼び出しを飛ばします — 更新は Claude Code の
OAuth フローの仕事で、ウィジェットはそれを真似しません。

レスポンス:

```json
{
  "five_hour": { "utilization": 36.0, "resets_at": "2026-09-09T09:04:59+00:00" },
  "seven_day": { "utilization": 4.0,  "resets_at": "2026-09-15T09:59:59+00:00" },
  "limits": [ ... ],
  "spend": { ... }
}
```

そのままウィジェットのフォルダーの `usage-cache.json` に保存します。

**Claude Code のファイルには絶対に書きません。** `~/.claude.json` は Claude Code
がまるごと書き直すファイルなので、外から同時に書くと状態が壊れかねません。
ウィジェットが失敗しても落ちても、Claude Code 側は影響を受けません。

### 2. `%USERPROFILE%\.claude.json` → `cachedUsageUtilization`

同じ数値ですが、Claude Code 自身が取得したときにしか更新されないキャッシュです。
何日も古いことがあります。1 が使えないときの備えです。

実測では、このキャッシュが 44 時間古いまま 5 時間 70% / 7 日 60% を指していた
一方、同じ瞬間に 1 で直接問い合わせた実際の値は 28% / 3% でした。ライブ呼び出しを
入れた理由がこれです。

### 3. `%USERPROFILE%\.claude\projects\**\*.jsonl` → assistant 行

```json
"usage": { "input_tokens": 2, "cache_creation_input_tokens": 25110,
           "cache_read_input_tokens": 29894, "output_tokens": 599 }
```

リクエストごとのトークン数とタイムスタンプ。ネットワークとは無関係に 5 秒ごとに
読み直します。常に最新ですが、サーバーの集計ではなく自前の集計です。

セッション枠に入る行だけを合算します。枠の開始 = `five_hour.resets_at` − 5 時間。

キャッシュ読み取りトークンは課金トークンの 20 倍を超えるので別に数えます。画面の
`tok` は課金トークン（input + output + キャッシュ書き込み）で、キャッシュ読み取り
はツールチップにだけ出ます。

### ユーザー名とプラン

`~/.claude.json` の `oauthAccount` ブロックから読みます — ネットワーク呼び出しは
ありません。

| フィールド | 用途 |
|---|---|
| `displayName` | ユーザー名 |
| `emailAddress` | ユーザー名のツールチップ |
| `organizationType` | プラン バッジ |

`organizationType` の対応: `claude_pro`→`Pro`、`claude_max`→`Max`、
`claude_max_5x`→`Max 5x`、`claude_max_20x`→`Max 20x`、`claude_team`→`Team`、
`claude_enterprise`→`Enterprise`。

ウィジェットの動作中に変わることはないので、ウィンドウ生成時に一度だけ読みます。

### 今どれを見ているか

`detail` スキンの最下行に取得元とその古さがそのまま出ます。

| 表示 | 意味 |
|---|---|
| `live now` | たった今 Anthropic から取得 |
| `live 12m` | 12 分前に取得した値 |
| `claude-code 2d` | ライブ失敗。Claude Code のキャッシュを使用中で 2 日古い |
| `token expired` | トークン期限切れ。Claude Code を一度起動すれば更新される |
| `http 429` | 呼び出しが多すぎ。次の周期で自然に解消 |
| `http 401` | 認証拒否。Claude Code に再ログイン |
| `sync failed` | ネットワーク エラーなど |

ウィジェットを再起動しても、キャッシュが `syncSeconds`（既定 300 秒）より新しけ
れば問い合わせ直しません。Claude Code のフックで頻繁に再起動されるときに
エンドポイントを叩いて `http 429` を招くのを防ぎます。`Sync now` はこの制限を
無視します。

`resets_at` がすでに過ぎていれば、その % は終わった枠のものなので**表示しません。**
代わりに自前のトークン集計を出します。古い数値を現在の値のように見せない、という
のがこのウィジェットの原則です。

金額（$）は表示しません。それを記録する `cost-state` 行はセッション終盤に書かれる
ため、進行中のセッション ファイルには存在しません。

## 設定

`config.json` はウィジェットが最初に終了したときに作られます。ほとんどは右クリック
メニューで変えられるので、直接開くことは稀です。

| キー | 既定 | 意味 |
|---|---|---|
| `skin` | `border2` | 起動時のスキン。存在しない名前なら既定に戻る |
| `opacity` | `0.92` | ウィンドウ全体の不透明度 |
| `left` / `top` | `-1` | 位置。`-1` なら右下に自動配置 |
| `pollSeconds` | `5` | ローカル ファイルを読み直す周期 |
| `syncSeconds` | `300` | Anthropic へ問い合わせる周期 |
| `autoSync` | `true` | 自動同期。オフなら `Sync now` のみ |
| `windowHours` | `5` | セッション枠の長さ |
| `warnPct` / `dangerPct` | `70` / `90` | 黄・赤に切り替わる位置 |

`usage-cache.json` は最後の同期レスポンスです。消しても構いません — 次の同期で
また作られます。

## トラブルシューティング

**ウィジェットが見当たらない**
`config.json` の `left` / `top` が、今はないモニターを指している可能性があります。
そのファイルを消して起動し直せば右下に戻ります。

**残り時間が Claude アプリ / Web と違う**
どちらも同じ `resets_at` を読むので、食い違う理由はありません。違うならウィジェット
が古い可能性が高いので、新しい版を確認してください。秒は切り捨てるため 1 分までの
差は想定内で、それ以上ならバグです。

**数値が止まっている**
長く起動しっぱなしのインスタンスかもしれません。`Exit` で閉じて起動し直してくだ
さい。残り時間は 5 秒ごとに再計算するので、正常なら 1 分ごとに 1 分減ります。

**最下行が `claude-code` のまま変わらない**
ライブ呼び出しが失敗し続けています。`Sync now` を押して理由を確認してください。
`token expired` なら Claude Code を一度起動してトークンを更新させます。

**`%` ではなくトークン数が出る**
手元にあるのが終わったセッション枠の値だけ、という意味です。`Sync now` を押すか、
Claude Code で `/usage` を一度実行してください。

**スクリプトの実行がブロックされる**
`ClaudMonWidget.exe`、`start-hidden.vbs`、上のコマンドはいずれも
`-ExecutionPolicy Bypass` をその起動にだけ適用します。それでも止まる場合は組織の
ポリシーの可能性があります。

## テスト

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File test-usage.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File test-menu.ps1
```

`test-usage.ps1` は TEMP に偽の `.claude` ツリーを作り、基準時刻まで固定して集計・
アカウント解析・取得元の優先順位・フォールバックを検証します。ネットワークを使わず
実際のログの中身にも依存しないので、いつ走らせても同じ結果になります。

`test-menu.ps1` は右クリック メニューが本当にラジオ ボタンとして動くかを確認します。
WPF の `MenuItem` にはラジオ モードがなく、放っておくと不透明度が同時に複数選択され
ます。

## ビルド

`icon.ico` と `ClaudMonWidget.exe` はコミット済みなので、アイコンかランチャーを
変えるときだけ必要です。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1
```

`System.Drawing` でアイコンを描き、`.ico` を手で組み立て、Windows に標準で入って
いる .NET Framework の C# コンパイラーでランチャーをコンパイルします。ダウンロード
するものはありません。

## スキンを自作する

`skins\<名前>.xaml` を 1 つ足すだけです。`widget.ps1` を触る必要はありません。

ホストは以下の名前を `FindName` で探し、**あるものだけ**埋めます。欲しいものだけ
入れてください。

| `x:Name` | 種類 | 入る値 |
|---|---|---|
| `Dot` | Shape | 状態の色 |
| `TxtMain` | TextBlock | 5 時間の使用率。値がなければ自前のトークン集計 |
| `TxtReset` | TextBlock | 5 時間リセットまでの残り (`3h 04m`)、不明なら `--` |
| `TxtWeek` | TextBlock | 7 日間の使用率 |
| `TxtWeekReset` | TextBlock | 7 日リセットまでの残り (`6d 5h`)、不明なら `--` |
| `TxtSub` | TextBlock | `563.0k tok / 249 req / live now` |
| `TxtUser` | TextBlock | ユーザー名（ツールチップにメール アドレス） |
| `TxtPlan` | TextBlock | プラン バッジ |
| `BarTrack` / `BarFill` | Border | 5 時間の進捗バー |
| `WeekTrack` / `WeekFill` | Border | 7 日間の進捗バー |
| `Root` | 任意のコンテナー | 右クリック メニューが付く場所 |

`Window` には `WindowStyle="None"`、`AllowsTransparency="True"`、
`Background="Transparent"` が必要です。高さは `SizeToContent="Height"` にしておく
と、フォント サイズが違っても切れません。

右クリック メニューに新しいスキンを載せるには、`widget.ps1` 上部の `$Skins` 配列と
`-Skin` パラメーターの `ValidateSet` に名前を足します。

```powershell
$Skins = @('simple1','simple2','border1','border2','detail')
```

`config.json` が存在しないスキン名を指していれば既定のスキンに戻ります。スキンを
消したり名前を変えたりしても、ウィジェットが起動自体を拒否することはありません。

## 既知の制限

- 自前のトークン集計が Anthropic の課金・制限計算と一致する保証はありません。画面の
  `%` はサーバーの値、`tok` はこちらの集計です。
- `/api/oauth/usage` は公開されたドキュメントのある API ではありません。Claude Code
  が使うものをそのまま使っています。レスポンスの形が変われば同期は
  `unrecognized response` を残し、**直前のキャッシュをそのまま保持します** — 表示が
  空になることはありません。
- クリック透過はありません。有効にすると右クリック メニューに届かなくなり、グローバル
  ホットキーの登録が付いてきます。
- Claude Code の更新で JSONL のフィールド名が変わると集計が 0 になり得ます。その場合
  もウィジェットは落ちず `--` を表示します。
- Windows 専用です。WPF に依存しています。

## PowerShell 5.1 で踏んだ地雷

直すときに同じ罠を踏まないよう書き残します。どれもエラーを出さず、静かに誤った値を
返す種類のものです。

- **`~/.claude.json` を `ConvertFrom-Json` で解析してはいけません。** 絶対パスを
  キーにしたプロジェクト マップが入っており、パーサーがキーを大文字小文字を区別せず
  扱うため、`c:\...` と `C:\...` が重複キーとして衝突し、解析全体が例外になります。
  必要な値だけ正規表現で取り出します。
- **`.ps1` に非 ASCII 文字を入れないこと。** BOM のないスクリプトは ANSI として読ま
  れ、文字が化けます。日本語などのラベルは XAML にだけ置き、XAML は UTF-8 と明示して
  読みます。同じ理由で、これらのファイルを `Get-Content | Set-Content` で往復させて
  はいけません。
- **`GetNewClosure()` したスクリプト ブロックは複製されたスコープで動きます。** 作成
  側が後から代入した `$script:` 変数も、囲む関数の中で定義された関数も見えません。
  共有状態はハッシュテーブル 1 つに入れて参照で渡し、ハンドラーが呼ぶ関数はスクリプト
  最上位に置きます。これを見落として `SourceInitialized` ハンドラーが途中で例外に
  なり、その後ろにあったポーリング タイマーが起動しませんでした。ウィジェットは平然と
  表示されたまま最初のフレームで止まっていました — 死んだウィジェットは目立ちますが、
  止まったウィジェットは目立ちません。今はポーリング タイマーを**最初に、無条件で**
  起動します。
- **`[int]` キャストは切り捨てではなく四捨五入です。** `[int]3.58` は `4` です。残り
  時間を `[int]$span.TotalHours` で計算したせいで、3 時間 34 分が `4h 34m` になりま
  した。分はそのまま正しいので全く自然に見え、ありもしない 1 時間の余裕があるように
  読めました。時間を切るときは `[math]::Floor` を使います。予算を表す数値は多い側に
  外れてはいけません。
- **`return $配列` はパイプラインで展開されます。** 呼び出し側は `byte[]` ではなく
  ボックス化された要素の `object[]` を受け取ります。`.Length` は正しいままなので
  アイコン ディレクトリは正常に見えるのに、`BinaryWriter.Write` が別のオーバーロード
  を選び、エントリごとに 1 バイトしか書きません — ヘッダーだけ完璧で画像のない
  108 バイトの `.ico` ができます。`, $配列` で返します。
- **`StrictMode 2.0` でパイプライン結果に `.Count` を使ってはいけません。** 結果が
  1 つだとスカラーが返り `.Count` がないと例外になります。引数の評価中に起きると
  その検査ごと飛ばされるので、テストが静かに通ったふりをします。`@(...)` で囲みます。
